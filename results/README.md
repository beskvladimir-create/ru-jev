# Стенд формулировок: Ру-Жев против Laya

Замерено 2026-11-04. Код: `beskvladimir-create/ru-jev`, коммит `80d75f7` плюс
правка `scripts/robustness.py` из следующего коммита (см. ниже).

## Что здесь лежит

| файл | что в нём |
|---|---|
| `bench_rujev_v11.jsonl` | Ру-Жев v1.1 построчно: вероятности, логиты, выбор |
| `bench_rujev_v13.jsonl` | Ру-Жев v1.3 (выложенные веса, `model/ru-jev-v1.3/ship`) |
| `bench_laya_instrA.jsonl` | Laya, инструкция «К какой категории относится запрос пользователя?» |
| `bench_laya_instrB.jsonl` | Laya, инструкция «Какая служба должна обработать этот запрос?» |
| `table.md` | сводка, собранная из четырёх файлов выше |

По 6000 строк в каждом: шесть словарей формулировок по 1000 вопросов.

## Как воспроизвести

```bash
# 1. выгрузить строки стенда (детерминированно)
python scripts/robustness.py --model model/ru-jev-v1.3/ship --n 1000 --dump bench_rows.jsonl

# 2. наши версии
python score_rujev.py --model model/ru-jev-v1.3/ship --rows bench_rows.jsonl \
  --out bench_rujev_v13.jsonl --tag ru-jev-v1.3

# 3. соседняя модель (pip install laya)
python score_laya.py --rows bench_rows.jsonl --out bench_laya_instrA.jsonl \
  --instr "К какой категории относится запрос пользователя?" --instr-id A

# 4. сводка
python aggregate.py "ru-jev-v1.1=..." "ru-jev-v1.3=..." "laya instr A=..." ...
```

Скрипты `score_rujev.py`, `score_laya.py` и `aggregate.py` лежат в скрадчпаде
сессии, их надо перенести в репозиторий кода перед публикацией чисел.

## Что надо знать, прежде чем смотреть в таблицу

**Это домашнее поле Ру-Жева, и разрыв по точности почти целиком об этом.**
Стенд построен на `mteb/amazon_massive_scenario` (ru). Обучающая часть MASSIVE
входит в обучающую смесь Ру-Жева с версии v1. Laya этой задачи не видела и идёт
здесь zero-shot, причём её собственная карточка прямо говорит «near chance on
typed-decisions zero-shot, 0.342». Сравнивать по колонке точности и делать вывод
«наша модель лучше» нельзя. Для честного сравнения нужны наборы, которых не
видела ни одна из моделей, это следующий замер.

**Что сравнимо и без домашнего поля.** Зазор между уверенностью и точностью и
остаточный ECE после подгонки своей температуры. Здесь Laya ведёт себя так же,
как наша v1.1 до исправления, только хуже: зазор +0.23 против +0.12 у v1.1 и
+0.03 у v1.3, и 110-125 уверенно неверных ответов на тысячу против 44.

**Асимметрия подачи, работающая против нас.** Ру-Жев получает только пару
(текст, вариант), без инструкции. Laya по своему устройству требует вопрос, то
есть получает подсказку, которой у Ру-Жева нет.

**Ключи вариантов у Laya нейтральные** (`o0`..`o4`), смысл несёт только значение,
то есть ровно та строка, которую видит Ру-Жев. Иначе Laya читала бы осмысленный
ключ вдобавок к тексту варианта.

**Две инструкции взяты затем, чтобы показать разброс по формулировке вопроса.**
Он мал, на жаргоне 0.394 против 0.419, так что результат Laya не объясняется
неудачной подсказкой.

**Точность выдачи Laya четыре знака после запятой.** В 0 и 2 строках из 6000
вероятность верного варианта пришла нулём, эти строки исключены из подгонки
температуры, на ECE они не влияют.

## Правка в стенде, без которой сравнение было бы недействительным

В `scripts/robustness.py` порядок вариантов задавался как
`random.Random(hash(text) & 0xffff)`. Хеш строк в Python солится от запуска к
запуску, поэтому порядок вариантов не воспроизводился. Заменено на
`zlib.crc32`.

На числа Ру-Жева это не влияет вовсе: он считает каждую пару (текст, вариант)
отдельным проходом, softmax берётся по независимым оценкам, порядок в результат
не входит. Проверено: все двенадцать опубликованных чисел по шести словарям
воспроизвелись до третьего знака.

На Laya влияет: она читает все варианты за один проход, и её карточка заявляет
позиционную предвзятость. Без фиксации порядка две модели видели бы разные
входы.
